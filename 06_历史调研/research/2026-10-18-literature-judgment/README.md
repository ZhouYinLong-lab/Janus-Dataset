# 用文献回答：阴性证据能否自动挖掘，挖出来是否值得用

日期：2026-10-18。本轮不做模型实验；以一手论文、公开方法和对照设置作判断。

## 本轮的问题

1. 不依赖高级通用大模型逐篇判读，现有技术能自动做到哪一步？
2. 实测阴性相对推定、随机或构造负例，在哪些任务中已显示收益，在哪些设置中没有？
3. 是否已有工作把文献恢复、可信数据记录、下游模型收益连接起来？领域不同的证据能否迁移？
4. 仅靠已有文献，我们能作出什么判断，什么仍不能回答？

## 阅读和记录约定

- 只把原论文、作者维护的仓库、正式数据库文档作为结论依据。综述用于追引，不替代原始实验。
- 区分题录检索、摘要阅读、正文方法与结果核查、补充材料核查，不用“读过”掩盖阅读深度。
- 每个量化结论记录指标、对照、数据划分、阴性定义、原文位置；未核实的控制项明确写出。
- 自动抽取中的“无关系”标签、文字否定、实测无活性不是同一对象；实体识别分数不等于完整记录的正确率。
- 标签来源、数量、化学空间、训练方法和测试分布可能一起变化，不把所有增益归于阴性标签本身。
- 不把“本轮未找到”写成“没有人做过”；不以公平实验尚不完美为由否定所有已有的实用收益。
- 原文可合法获取则留存，记录URL和哈希；访问失败照实记，不绕过付费或访问控制。
- 复核旧论文与新纳入论文分开。固定历史材料不回写成当时已知的新结论。

## 原文与机器可读文件

- `utility/sources/`：初始下载的药物活性来源。访问挑战页已明确识别，不作证据。
- `extraction/sources/`：初始下载的否定抽取来源。
- `bridge/sources/`：主助手后续取得的酶、抽取及跨领域一手来源。
- `followup/`：[第二轮逐篇核查](followup/逐篇核查.md)、17项补充视图、15份全文与2份摘要元数据、下载记录和检查结果。
- `*/reading_text/`：原文机器转换，便于搜索；最终表格以原XML/PDF为准。
- `bridge/page_checks/`：部分关键PDF页的核对图。是否真正视读见阅读记录。
- `source_inventory.csv`：全部原始文件的标题、标识、内容类型检查及SHA256。
- `bridge/source_manifest.json`：主助手下载的URL、结果和哈希，含失败项。
- `与已有文献矩阵的对应.csv`：按URL/DOI对应旧矩阵，不把未匹配说成首次发现。
- `verification.json`：文件完整性核查结果；不是科学复现或专家验收。

三个并行助手因额度限制没有完成报告；主助手继续检索、解析并核查主要证据。没有把并行任务当成已完成交叉验证。子目录数量和论文数量不作为质量指标；本轮是有记录的定向证据综述，不是PRISMA系统综述或新实验报告。没有提交、推送或导入Zotero。

可重跑原文转换和结构检查：

```powershell
D:/Environment/Miniconda3/python.exe research/2026-10-18-literature-judgment/build_reading_texts.py
D:/Environment/Miniconda3/python.exe research/2026-10-18-literature-judgment/audit_review.py
```

下载脚本支持在命令后指定来源文件名，只重试选定来源；无参数会遍历来源表。脚本不运行模型、不调用推理API，也不生成或推断阴性标签。
