# 提取管线是什么

管线就是一组按固定顺序工作的程序：输入论文，找出正文中的阴性实验结果，补上必要条件，检查原文出处，最后保存成数据文件。

它对应我们四步研究路线中的第1步，给后面的数据汇总提供记录。目前的启动文件是 [batch.py](batch.py)，它会调用其他脚本完成各个步骤。

## 从输入到输出

```text
已取得的论文全文（目前主要支持可读XML）
                  ↓
整理正文、表格和图注，切成适合模型读取的小段
                  ↓
调用模型：寻找正文中的阴性实验原句
                  ↓
调用模型：结合相关方法和表图，提取分子、靶标、结果及条件
                  ↓
自动核对引文出处，并按规则筛查；有问题的记录分开保存
                  ↓
输出 JSON / CSV 文件，供后续核查和数据汇总使用
```

例如，一句“化合物15失去降解能力”，需要进一步对应到哪个蛋白、哪种细胞、多少剂量、处理多久，以及原句在哪里。论文没有给出的内容保留为空。

## 这些步骤对应哪些文件

| 工作 | 主要文件 |
| --- | --- |
| 总入口：准备、启动、续跑、导出 | [batch.py](batch.py) |
| 读全文并分段 | [corpus.py](corpus.py)、[prepare.py](prepare.py) |
| 找到结果所指的表格、图注等上下文 | [linked_context.py](linked_context.py) |
| 调用模型完成寻找原句、补充条件两步 | [batch_run.py](batch_run.py)；要求写在 [discovery.md](discovery.md)、[enrichment.md](enrichment.md) |
| 检查引用和记录规则 | [contract.py](contract.py)、[batch_contract.py](batch_contract.py) |
| 保存结果及问题清单 | [batch_export.py](batch_export.py) |
| 限制调用次数、记录用量 | [batch_budget.py](batch_budget.py) |

先认识 `batch.py` 这个入口即可，不需要先看懂全部脚本。模型只是其中一个环节；读文件、组织材料、保存进度和导出数据也属于管线。

## 实际结果放在哪里

本轮工作目录是 `local/repair_regression_01/`。以下文件只在本机保存，不随代码上传：

- `exports/records.csv`：可以用Excel打开的提取表。
- `exports/records.json`：同一批直接通过自动检查的记录，方便程序继续处理。
- `exports/quarantine.json`：没有通过检查的记录及原因。
- `exports/unresolved.json`：还没有处理清楚的候选。
- `exports/summary.json`：本轮处理情况和数量汇总。
- `citation_recovery/combined_records.json`：另行补齐可确定出处后的合并结果；实验字段不改，科学内容仍需核查。

每条记录包含分子、靶标、实验终点、条件、结果、原文出处和审核状态。它们目前是候选实验记录，还不是全部确认可靠、可直接训练的数据集。

## 目前到哪一步

已有可执行的管线和真实输出，也已修复三处程序问题。实际运行仍会遇到漏条件、误解结果等情况，部分记录需要复核。

数据筛选汇总、接入大模型检索或训练小模型、使用已有benchmark评价，是后续三个环节，不能用“管线能运行”代替它们完成。
