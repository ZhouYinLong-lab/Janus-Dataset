# 调研报告：酶工程突变体—反应功能预测与失败变体挖掘

**调研结论：成功（推荐作为本项目的主典型场景）**  
**建议场景名称：**定向进化酶工程中的突变体—反应功能预测与失败/低性能变体挖掘。

## 1. 场景定义

以酶工程和定向进化论文为对象，抽取“酶序列/突变体—反应或底物—实验条件—活性/fitness”的关系，重点恢复被忽略的低活性、失活、功能丧失和增益不明显的变体记录。下游任务不是简单预测“哪个突变更好”，而是比较：

1. 只使用传统正向样本时，模型是否高估突变体性能；
2. 加入失败和低性能变体后，模型是否能更准确地识别不可行突变和性能边界；
3. 文献中抽取的实验条件、测定方法和失败原因能否改善跨论文泛化。

## 2. 为什么它满足“典型场景”要求

该场景同时具备三项条件：

- 有明确的公开数据资源和可复现的序列—功能预测任务；
- 失败/低性能变体数量真实存在，且与成功变体共享同一酶、同一反应或相近实验条件，属于有判别价值的困难阴性样本；
- 关键数据并非全部在数据库中，许多信息分散在论文正文、图、补充表和不同命名体系中，确实需要进行文献级的信息恢复。

## 3. 公开资源与文献挖掘规模核验

核心依据是 [Enzyme Engineering Database（EnzEngDB）论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC12807667/)，以及其[官方代码仓库](https://github.com/fhalab/EnzymeEngineeringDB)和[Zenodo 数据发布](https://zenodo.org/records/17310823)。

| 核验对象 | 公开结果 | 对本项目的意义 |
|---|---:|---|
| 人工整理 gold-standard | 40 篇论文、6,234 条 sequence-function entries、635 个 reactions、1,846 个 unique variants | 有明确的文献级标准答案和实体关系 |
| 自动文献挖掘候选 | 检索 912 篇 DOI 论文，得到 327 篇候选稿件 | 说明文献规模足以支持自动抽取研究 |
| 完整记录恢复 | 133 篇论文恢复出 complete records | 具备可评估的“是否抽全”标准 |
| 自动抽取质量 | 64% 的自动抽取需要人工介入；基准中约 30% 可直接通过 | 问题真实存在，且有清晰的模型/抽取改进空间 |
| 扩展抽取结果 | 102 篇论文新增约 2,415 条记录，覆盖 818 个 variants、1,078 个 reactions | 文献抽取带来实质性规模增量 |
| 数据库公开规模 | 网站说明已收集超过 10,000 条实验记录 | 可支持模型训练、验证和跨文献划分 |

论文明确指出，现有蛋白质/酶数据库通常偏重正向结果，负向变体和功能丧失信息容易被忽略；而酶工程数据分散于正文、图和补充文件中，自动抽取后仍需人工复核。这与本项目“非结构化阴性数据挖掘”的问题定义高度一致。

## 4. 官方数据包的直接核验

为避免只依据论文摘要，本轮下载并检查了 Zenodo 官方数据包 `EnzEngDB Data.zip`。当前数据发布版本中：

| 数据层级 | 直接核验结果 | 说明 |
|---|---:|---|
| experiment CSV 文件 | 179 个 | 覆盖多类酶工程实验任务 |
| 全部实验行数 | 462,092 行 | 不同实验的 fitness 量纲不完全相同，不能直接合并成单一比例 |
| 有数值 fitness 的记录 | 458,598 行 | 具备可用于排序或分类的性能字段 |
| `fitness_value = 0` | 6,347 行 | 直接存在完全无功能/零 fitness 记录，但需结合实验定义解释 |
| 文献挖掘子集 `exp_LLM*.csv` | 102 个实验文件、约 2,425 行 | 与论文所述 102 篇文献抽取结果对应；版本差异使行数略高于论文中的 2,415 条 |
| 文献挖掘子集中 `fitness_value = 0` | 45 行，分布于 15 个实验文件 | 这些记录可回连 DOI 和论文，证明文献抽取结果中确实包含失败/零性能样本 |

文献挖掘子集中的零 fitness 记录分布于多个 DOI 关联实验，而不是集中在一个人工构造的负样本文件中。例如，`Photoenzymatic Enantioselective Intermolecular Radical Hydroamination`、`Artificial Metalloenzymes based on TetR proteins and Cu(II)`、`Electricity-driven enzymatic dynamic kinetic oxidation` 和 `Engineered Enzymes Enable Selective N-Alkylation of Pyrazoles With Simple Haloalkanes` 等实验文件均包含零 fitness 记录。

需要强调：不同实验的 fitness 定义和尺度可能不同，因此不能把全库所有“小于某阈值”的记录简单称为阴性比例。当前报告只将 exact zero 作为稳妥的直接核验结果，并建议后续按实验任务重新定义“低性能”阈值。

## 5. 阴性数据的科学价值

这个场景中的阴性不是“没有被报道”，而是与具体实验和变体绑定的失败结果：

| 阴性类型 | 典型含义 | 可用于的模型优化 |
|---|---|---|
| fitness 为 0 / 无活性 | 变体在给定反应和测定体系下无可检测功能 | 纠正模型把所有突变都视为可行的偏差 |
| 活性显著低于野生型 | 变体仍有信号，但性能不足以支持筛选或应用 | 学习连续性能边界，而不是只做成功/失败二分类 |
| gain-of-function / loss-of-function 对照 | 同一酶工程实验中同时存在改进和退化方向 | 构造同背景、同任务的困难负样本 |
| 条件依赖的低性能 | 活性下降可能来自底物、反应条件或测定方法 | 将实验条件作为模型输入，减少跨实验误判 |
| 序列相近但功能相反 | 相邻突变产生不同结果 | 用于检验模型对局部序列变化和非加和效应的敏感性 |

这类负样本比“数据库中不存在的配对”更有价值，因为它们具有明确的实验发生关系；同时，论文中的实验条件、变体命名、结果阈值和失败原因能够补充结构化数据库通常缺失的上下文。

## 6. 下游任务与验证方案

建议将主任务收窄为：

> 给定酶的野生型序列、突变体序列、目标反应和实验条件，预测突变体的功能等级，并识别可能失活或低性能的变体。

模型对照可以分三组：

| 对照组 | 输入数据 | 目的 |
|---|---|---|
| A | 仅使用成功/高性能记录 | 测量正样本偏置 |
| B | 加入结构化失败/零 fitness 记录 | 测量显式阴性对模型边界的改善 |
| C | 在 B 基础上加入文献正文、图表和补充材料中的条件/原因信息 | 测量非结构化科学证据的增量价值 |

评价时按论文或实验批次划分训练集和测试集，避免同一论文中的近重复变体泄漏。建议报告 AUROC、AUPRC、低性能召回率、排序质量，以及在独立论文上的跨文献泛化性能。

## 7. 风险与边界

| 风险 | 处理方式 |
|---|---|
| 不同论文的 fitness 定义不同 | 按实验/测定体系归一化，先做同任务分类，再扩展连续值预测 |
| 低活性、低表达和不稳定可能混杂 | 单独记录表达、稳定性、催化活性和测定失败原因 |
| 文献抽取仍需要人工复核 | 将人工复核作为金标准和误差分析环节，不把自动抽取直接视为真值 |
| 当前数据库覆盖存在偏倚 | 采用按论文、酶家族和反应类型分组的外部测试，报告适用边界 |
| 论文与数据发布版本存在小幅差异 | 在数据版本、下载日期和统计口径中明确记录；不追求不加说明的数字一致 |

## 8. 结论

**结论：成功，推荐作为申报书的主典型场景。**

该场景不是因为“有一个现成数据库”而成功，而是因为它同时满足：

1. 有公开、可复现的酶工程序列—功能数据和文献挖掘基准；
2. 数据中确实存在可回连到实验和 DOI 的零性能/失败变体；
3. 论文中还存在数据库字段之外的实验条件、失败原因、命名映射和上下文信息；
4. 加入阴性数据后可以直接定义模型优化对照，而不是停留在“抽取结果展示”。

建议在申报书中以此为例，形成“文献阴性证据抽取—实体与实验对齐—困难负样本构建—模型优化—跨任务迁移”的通用方法框架，再拓展到转氨酶底物相容性、蛋白稳定性突变和结构测定流程失败等任务。
