# 群聊决策落实：申报书场景、题目与原型系统

## 一、当前团队决策

根据群聊讨论，申报阶段先采用一个任务清晰、benchmark 和模型基础较成熟的领域完成填报，后续再扩大调研并迁移到其它生化任务。当前暂定典型场景为：

> **酶—底物动力学参数预测中的不可测、低活性与低于检测限阴性证据挖掘。**

最终交付物采用“原型系统”，不使用“演示系统”。原型系统应能够真实运行基本流程，而不是只展示静态页面或预设结果。

## 二、必须明确的阴性数据边界

“没有收录动力学参数”不能直接标成阴性，必须区分：

| 情况 | 是否属于阴性数据 | 处理方式 |
|---|---|---|
| 文献没有测量或没有提及 `kcat`、`Km` | 否 | 记为未知/未测，不进入阴性数据集 |
| 论文测量了，但数据库漏收了明确数值 | 否，属于遗漏的定量数据 | 可用于信息抽取和数据库补全，但不作为阴性样本 |
| 已开展实验，但无可检测活性或产物 | 是 | 记为定性阴性或低于检测限 |
| 活性低于检测限，不能得到可靠参数 | 是 | 记为左删失/区间标签，不伪造具体数值 |
| 无法拟合 Michaelis–Menten 参数 | 视原因而定 | 若由低信号或无饱和导致，可作为参数不可确定事件；技术错误单独记录 |
| 参数显著低于野生型或实用阈值 | 是，但阈值需明确 | 记为低性能样本，并保存比较对象和实验条件 |
| 表达、纯化或检测仪器失败 | 不是催化活性阴性 | 记录为技术失败，不与酶—底物阴性混合 |

项目要挖掘的是**已发生实验且结果不理想**的证据，而不是把未知值、未测值和数据库空值当成负例。

## 三、为什么这个场景可以成立

CatPred-DB 提供 `kcat`、`Km` 和 `Ki` 预测 benchmark。其建库过程要求记录至少包含一个明确数值参数、酶类型、底物/反应信息，并能映射到酶序列；缺少必要注释的记录会被排除。由此形成的 benchmark 适合数值回归，但难以直接容纳“无可检测活性”“低于检测限”“参数无法确定”等没有精确数值的实验结果。

这为项目提供了明确的数据缺口：

| 现有数值型数据集 | 文献非结构化阴性证据可补充的内容 |
|---|---|
| 酶序列、底物结构、`kcat/Km/Ki` 数值 | 无可检测活性、低于检测限、无法确定参数 |
| 部分 pH、温度和反应注释 | 更完整的实验条件、酶变体、辅因子和测定方法 |
| 单一数值标签 | 上限/下限、区间标签、定性等级和失败原因 |
| 野生型数值数据为主 | 突变体的低性能、失活和条件性失败记录 |

公开资料：

- [CatPred 论文及 CatPred-DB 建库方法](https://www.nature.com/articles/s41467-025-57215-9)
- [CatPred-DB 数据集说明](https://huggingface.co/datasets/RosettaCommons/CatPred-DB)
- [BRENDA 数据字段说明](https://www.brenda-enzymes.org/datafields.php)
- [SABIO-RK 数据库说明](https://sabio.bioquant.uni-heidelberg.de/layouts/content/about.gsp)

当前可以确认任务和数据缺口逻辑成立，但尚未确认正文严格阴性证据的实际规模。申报书中应将其写成需要研究和验证的问题，不能写成已经获得大量数据。

## 四、推荐项目题目

### 推荐版本

> **生化文献非结构化阴性数据挖掘与模型利用方法及原型系统研究**

该版本同时体现：

- 研究对象：生化文献中的非结构化阴性数据；
- 方法内容：数据挖掘与模型利用；
- 最终交付：原型系统；
- 项目属性：方法研究，而不是只开发软件。

### 可选版本

> **面向生化文献的非结构化阴性数据挖掘、模型利用与原型系统研究**

不建议使用“分析算法与演示系统”，因为它会把研究范围缩窄为算法展示，也弱化系统需要实际运行的要求。

## 五、申报书中的典型场景表述

### 简洁版

> 本项目拟以酶—底物动力学参数预测为典型场景，研究科学文献中无可检测活性、低于检测限、参数无法可靠确定及显著低性能等非结构化阴性证据的识别、抽取与标准化方法，并探索其在酶动力学参数预测和不可测风险识别中的模型利用方式。在此基础上，将所形成的方法迁移至酶—底物相容性、蛋白互作和蛋白质结构测定失败等任务，验证方法的通用性。

### 项目简介可用版

> 现有酶动力学参数数据库和预测 benchmark 主要收录具有明确数值的 `kcat`、`Km` 和 `Ki` 记录，适合训练常规回归模型；然而，论文正文中还存在无可检测活性、低于检测限、动力学参数无法可靠确定及显著低于对照等实验结果。这类结果反映了酶—底物组合的不可行区域和模型预测边界，却难以直接进入只接受精确数值标签的现有数据集。本项目拟以酶—底物动力学参数预测为典型场景，研究阴性证据识别、酶与底物实体对齐、实验条件恢复、数据库去重和删失标签表示方法，构建可追溯的非结构化阴性证据数据，并比较仅使用现有数值数据与加入真实阴性证据后模型在参数预测、低活性识别和跨酶家族泛化方面的表现。在此基础上，形成可迁移的生化文献阴性数据挖掘与利用框架，并开发可运行的原型系统。

## 六、下游模型不能只做普通数值回归

建议把任务设计为三个相互关联的子任务：

| 子任务 | 输入 | 输出 | 推荐指标 |
|---|---|---|---|
| 动力学参数回归 | 酶序列/结构、底物结构、实验条件 | `log10(kcat)`、`log10(Km)` 等 | MAE、RMSE、Spearman |
| 不可测/低活性分类 | 酶、底物、条件 | 是否无可检测活性或无法获得参数 | AUROC、AUPRC、MCC、阴性召回率 |
| 删失回归 | 酶、底物、条件及检测界限 | 数值区间或上限/下限 | 删失似然、区间覆盖率、排序指标 |

模型对照设置：

| 组别 | 数据 |
|---|---|
| A | 现有数据库中的精确数值记录 |
| B | A + 随机构造负例 |
| C | A + 文献抽取的真实不可测/低活性/删失阴性证据 |

只有 C 相对 A、B 的结果才能回答“非结构化阴性数据是否改善模型”。

## 七、迁移性应当作为实验问题

“一个阴性样本能够迁移到结构相似酶或相似底物”是合理假设，但不能直接当作既定事实。建议采用以下划分验证：

- 按酶序列相似性或家族划分训练集和测试集；
- 按底物骨架划分训练集和测试集；
- 单独评估同家族迁移、跨家族迁移和新底物泛化；
- 检查真实阴性数据是否减少模型对相似但不可行组合的误判。

这样能够把“可迁移性较强”转化为可评价的研究问题。

## 八、原型系统应实现的最小闭环

原型系统至少包含以下模块：

1. 导入论文 PDF、题录或全文；
2. 识别无活性、低于检测限、无法拟合和低性能等候选证据；
3. 抽取酶、变体、底物、反应条件、结果类型和原文位置；
4. 与 CatPred-DB、BRENDA 或 SABIO-RK 条目进行实体对齐和去重；
5. 将结果表示为精确数值、区间/删失标签或定性阴性类别；
6. 人工复核证据并导出结构化数据；
7. 运行数值基线与阴性增强模型，展示评价指标和错误案例。

完成上述流程即可称为“可运行原型系统”；如果只有上传页面、抽取结果展示或预设案例，则只能称为演示系统。

## 九、当前结论

**酶动力学参数预测可以用于申报书，但不能以“缺失数值就是阴性数据”为逻辑。**正确主线是：

> 现有 benchmark 主要依赖精确数值标签，论文中的不可测、低于检测限和显著低性能结果难以进入数据集；项目将这些非结构化阴性证据表示为分类或删失标签，并验证它们对动力学参数预测和不可测风险识别的作用。

这套表述既保留了成熟 benchmark 和数值回归任务，也真正体现了“非结构化阴性数据挖掘与利用”。
