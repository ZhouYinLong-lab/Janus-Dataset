# 新一轮交流内容的证据化调研与研究缺口判断

> 调研日期：2026-09-16  
> 主题范围：BRENDA/酶学数据、阴性监督、文献数据抽取、结构化科研数据与模型验证  
> 本文目的：把交流内容拆成可核查的论断，区分“已有工作”“合理推断”“仍需实证的问题”。

## 0. 先给结论

目前最稳妥的判断不是“没人做过阴性数据”，也不是“只要把 BRENDA 改成 JSON 就是新工作”。已有工作已经覆盖了：

- 大规模酶学数据的结构化和人工整理（BRENDA）；
- 反应动力学及实验条件的标准化（SABIO-RK、STRENDA、EnzymeML）；
- 实验阴性/低活性记录、完整筛选矩阵和失败实验在若干具体资源中的保存；
- 正例—未标注数据学习、推定负例、弱监督和文献结构化抽取；
- 连续活性预测、排序学习、校准和严格的分布外评价。

因此，以下说法不能直接作为创新点：

1. “BRENDA 没有结构化字段”；
2. “阴性数据此前没人用过”；
3. “把 0/1 扩展成多个字段就是新的监督学习范式”；
4. “让大模型输出 JSON 就解决了科研数据抽取”；
5. “所有机器学习都因为缺字段而无法训练”；
6. “没有人做过酶学 AI-ready 数据集”。

本轮检索后，最可能成立且值得继续验证的研究缺口是：

> 针对一个明确的酶学任务，构建观察级、来源可追溯的监督记录，明确区分实测阳性、实测阴性/低于检测限、未测试/未知、推定标签和删失值，同时保留实验条件与证据片段，并用严格的外推划分检验这些记录是否带来超出“样本量增加”和“类别平衡”的独立收益。

这是一个“数据语义—证据追踪—任务验证”组合问题，而不是单纯的数据库扩充问题。是否真的没人把这几部分放在一起，需要通过小规模系统检索和可复现实验确认，不能仅凭目前资料宣布绝对空白。

## 1. 对交流内容的逐条核查

### 1.1 “BRENDA 可以作为入口”——成立，但不能把它当成空白资源

BRENDA 是成熟的酶学数据资源，不是尚未整理的原始文献集合。BRENDA 2026 论文报告其知识图谱包含约 580 万个数据点、112,288 个酶、15,335 个生物体和 173,164 篇参考文献，并且包含人工评估、文本/数据挖掘、外部数据和预测数据等不同来源。数据可按 CSV、JSON、TXT 下载，提供公共 SPARQL 端点，并与 PubMed、UniProt、PDB 等资源链接。

依据：

- [BRENDA in 2026](https://academic.oup.com/nar/article/54/D1/D527/8315798)
- [BRENDA 官方下载页](https://www.brenda-enzymes.org/download.php)
- [BRENDA 2.0 JSON schema](https://www.brenda-enzymes.org/schemas/2.0.0/brenda.schema.json)

BRENDA 2026 年统计页还列出 80,377 个 IC50 值、49,409 个 Ki 值、186,457 个 Km 值、94,073 个 turnover number、325,298 个 inhibitor 记录和 566,851 个 substrate/product 记录。这个数量级足以说明：研究起点不是“从零做酶学数据集”，而是分析其记录语义、覆盖边界和下游可用性。

依据：[BRENDA Statistics](https://www.brenda-enzymes.org/statistics.php)。

### 1.2 BRENDA 的“字段多”不等于“观察记录完整”——这是一个关键可检验点

BRENDA 的 schema 已经包含反应、底物/产物、Km、kcat、Ki、IC50、pH、温度、稳定性、抑制剂、蛋白变体、来源组织、蛋白和参考文献等字段。也就是说，“没有字段”不是准确表述。

但统计页的计数是按酶—生物体—蛋白—评论—参考文献等特定组合统计的出现次数；它不是每条实验观察的完整率，也不能证明某个活性值同时拥有完整的 pH、温度、底物浓度、酶浓度、检测限和失败原因。因此需要区分：

| 层次 | 已有证据 | 还不能由此推出的结论 |
|---|---|---|
| 资源层 | BRENDA 有大量字段、下载格式和文献链接 | 每条记录都适合直接训练模型 |
| 字段层 | 许多字段在 schema 中有定义 | 不同字段在同一观察上的联合覆盖率很高 |
| 语义层 | 有 value、comment、reference 等信息 | 记录已统一区分实测阴性、未测试和推定阴性 |
| 任务层 | 有活性、抑制和动力学数据 | 已经形成与某个具体预测任务匹配的 benchmark |

这个差异本身可以做成第一项审计：以“观察级记录”为单位统计字段共现、证据类型、实验条件、单位、检测限和文献定位，而不是只报告数据库总条目数。

### 1.3 “科学数据结构化是瓶颈”——有直接证据，但需要避免绝对化

酶学数据结构化和实验条件标准化并不是没人研究。SABIO-RK 以“一个生物体在特定条件下的一条反应”为基本记录，并由人工提取、专家审校和一致性检查维护；STRENDA 为酶动力学数据提出最低报告要求；EnzymeML 用 XML 组织反应条件、时间序列、动力学参数和模型。

依据：

- [SABIO-RK 2018](https://pmc.ncbi.nlm.nih.gov/articles/PMC5753344/)
- [STRENDA DB](https://pmc.ncbi.nlm.nih.gov/articles/PMC6005732/)
- [STRENDA Guidelines](https://www.beilstein-strenda-db.org/strenda/public/guidelines.xhtml)
- [EnzymeML specification](https://enzymeml.github.io/documents/specifications/)
- [EnzymeML, Nature Methods](https://www.nature.com/articles/s41592-022-01763-1)

另一方面，文献中的信息缺失确实普遍存在。对 11 篇近期论文的审查发现，每篇都缺少某些影响复现的关键信息；对 100 篇 SABIO-RK 来源论文的分析显示，45% 没有报告酶浓度，11% 没有底物浓度，11% 没有温度，4% 没有 pH，且补充材料也不能完全消除缺失。

依据：[An empirical analysis of enzyme function reporting](https://pmc.ncbi.nlm.nih.gov/articles/PMC6258184/)。

因此更准确的表述是：

> 酶学数据的标准化框架已经存在，但历史文献中的观察级信息仍存在缺失、分散、条件不一致和语义不明确；尚需验证的是，这些问题在负结果和未成功结果上是否更严重，以及能否通过来源可追溯的抽取和标注改善具体模型任务。

### 1.4 “阴性数据很难找”——对特定任务成立，不应泛化到所有分子科学

在蛋白序列—功能预测和定向进化场景中，阴性监督的确是明确问题。Song 等人在 Cell Systems 的研究指出，大规模定向进化/深度突变扫描数据常常只有富集后的正向序列，负序列难以通过高通量筛选获得，因此形成 positive-unlabeled（PU）学习问题。

依据：[Inferring protein sequence-function relationships with large-scale positive-unlabeled learning](https://pmc.ncbi.nlm.nih.gov/articles/PMC7856229/)。

但在另一个相近领域，蛋白功能预测的“负例选择”已经有专门研究。NoGO 工作指出，GO 中很少直接记录负例，缺少注释不等于功能为负，并比较了多种负例选择策略。因此“利用阴性数据”本身已经是已知方向；可创新的是负例的证据等级、实验上下文和下游增益验证。

依据：[Negative Example Selection for Protein Function Prediction](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1003644)。

### 1.5 “0/1 不够，需要更丰富的监督”——方向合理，但相关方法已有很多

酶学建模中已经存在连续活性回归、pairwise ranking、偏好/排序目标、不确定性估计和多任务学习。比如近期酶工程工作同时使用 pairwise ranking 与 pointwise MSE 来预测变体适应度，说明“从二元标签扩展到等级或连续值”并不是新的概念。

依据：

- [Rank-guided learning accelerates automated enzyme engineering](https://www.nature.com/articles/s41467-026-76264-2)
- [Descriptor-augmented ML for enzyme-chemical interactions](https://pmc.ncbi.nlm.nih.gov/articles/PMC10915406/)
- [A combinatorially complete epistatic fitness landscape](https://pmc.ncbi.nlm.nih.gov/articles/PMC11317637/)

真正值得研究的不是“字段变多”，而是监督语义是否被正确保存。例如：

| 原始情况 | 不宜直接编码为 | 更合理的记录 |
|---|---|---|
| 实测有活性 | 1 | value、单位、条件、误差、证据位置 |
| 实测无可检测活性 | 0 | censored/LOD、检测方法、条件、证据位置 |
| 论文未提及 | 0 | unknown / not reported |
| 实验未做 | 0 | untested |
| 由规则或模型推断 | 0/1 实测标签 | inferred、来源规则、置信度 |
| `IC50 > 10 μM` | 0 | 右删失值及阈值 |

这组区别若能被抽取、验证，并显示对外推任务有独立帮助，才构成比普通字段扩展更具体的研究问题。

### 1.6 “LLM 可以输出 JSON”——成立，但 JSON 不是科学正确性

已有工作已经使用大语言模型从科学文本中抽取实体、关系、合成步骤和实验条件，并输出 JSON 或其他结构化格式。例如材料科学文本抽取、合成步骤抽取和 ReactionSeek 都说明了 schema-guided extraction 的可行性。

依据：

- [Structured information extraction from scientific text with LLMs](https://pmc.ncbi.nlm.nih.gov/articles/PMC10869356/)
- [Extracting structured data from organic synthesis procedures](https://pmc.ncbi.nlm.nih.gov/articles/PMC11322921/)
- [ReactionSeek](https://www.nature.com/articles/s41467-026-70180-1)
- [From text to insight: LLMs for chemical data extraction](https://pubs.rsc.org/en/content/articlehtml/2025/cs/d4cs00913d)

已有证据同时显示：格式合规、语义正确、化学实体正确、来源证据正确不是一回事。LLM 可能生成格式正确但化学实体或关系错误的 JSON；因此研究中至少要分别评价字段级 precision/recall/F1、数值/单位正确性、实体链接、条件完整性和证据片段对应关系。

弱监督也已经有成熟先例。Snorkel 化学反应抽取用多个 labeling functions 输出 TRUE/FALSE/ABSTAIN，再学习噪声标签的组合；这证明伪标签可以用于规模化抽取，但也证明必须保留 abstain、噪声和置信度，不能把伪标签当成观察事实。

依据：[Extracting chemical reactions from text using Snorkel](https://pmc.ncbi.nlm.nih.gov/articles/PMC7251675/)。

### 1.7 “多字段等于可解释性/CoT”——不能直接等同

如果字段包含原始数值、条件、参考文献、页码/表格/句子位置和人工核验状态，它们可以构成证据可追溯性，并帮助解释模型输入来源。

但“生成一段理由”不自动等于可解释性。链式思考研究已经发现，模型输出的 reasoning 可能与其真实决策过程不一致。因此本项目若需要解释性，优先定义为“可审计证据链”：原文 span、记录 ID、实验条件、抽取规则、置信度和人工核查结果；不要把自由生成的 CoT 当成事实证明。

依据：[Measuring Faithfulness in Chain-of-Thought Reasoning](https://arxiv.org/abs/2307.13702)。

### 1.8 “缺字段会影响机器学习”——对固定输入模型成立，但不应说成所有 AI 的共同限制

缺失输入特征、单位不一致、条件不完整会影响固定 schema 的监督学习、回归、排序和数据拆分；但不同模型可以使用缺失值掩码、集合输入、图结构、文本上下文或 PU 学习来处理部分缺失。因此应改成任务化论断：

> 对需要把每条实验观察转换为固定输入—输出样本的模型，缺失或混淆的条件字段会造成标签噪声、不可比样本和评估偏差；其影响大小需要在指定任务和指定划分上实测。

## 2. 已有工作地图：哪些已经有人做，哪些仍可能有空间

| 方向 | 已有工作达到的程度 | 不能再直接声称的创新 | 仍可检验的缺口 |
|---|---|---|---|
| 大型酶学库 | BRENDA 已有大规模人工整理、字段体系、下载格式、文献链接和知识图谱 | “第一次结构化酶学数据” | 观察级字段共现、证据类型和任务可用性的系统审计 |
| 动力学标准 | SABIO-RK、STRENDA、EnzymeML 已有条件、单位、模型和 FAIR 规范 | “第一次定义酶学数据 schema” | 这些规范在历史阴性/失败记录上的覆盖与落地情况 |
| 实验阴性 | 若干数据库保留 inactive、低活性、完整筛选矩阵或失败实验 | “没人保存过阴性数据” | 阴性类型是否被区分，是否保留上下文和检测限 |
| PU/负例推定 | PU 学习、NoGO、弱监督已有方法 | “第一次使用负例/伪负例” | 实测阴性、未测试和推定负例的对照评估 |
| 文献抽取 | LLM、规则、弱监督和化学知识图谱抽取已有大量工作 | “LLM 能抽 JSON 是创新” | 负结果、删失值、失败原因、证据定位的专门 benchmark |
| 丰富输出 | 回归、排序、偏好学习和不确定性估计已有 | “0/1 改成多字段就是新学习范式” | 字段/标签语义清理是否带来独立模型收益 |
| 可解释性 | provenance、证据链接和模型解释研究已有 | “更多字段自动产生可解释性” | 证据链是否正确，且是否改善人工审计或模型信任 |
| 酶学 benchmark | 已有酶分类、反应检索、序列功能和工程优化 benchmark | “没有酶学 AI benchmark” | 阴性—未知—条件分层的统一 benchmark 仍需核查 |

### 2.1 最值得继续验证的组合缺口

在本轮检索范围内，没有发现一个成熟工作同时做到以下全部事项：

1. 面向一个明确酶学预测任务；
2. 从历史论文正文、表格和补充材料中恢复观察级记录；
3. 明确区分 positive、observed negative/low activity、untested/unknown、inferred 和 censored；
4. 保存原文证据位置、实验条件、检测限和数据来源；
5. 把提取结果与 BRENDA/SABIO-RK 等已有资源对齐；
6. 在控制样本数、类别比例、数据泄漏和拆分策略后，检验不同监督类型是否有独立下游收益。

这不是“绝对无人做过”的结论，而是一个中等置信度的组合缺口。下一步需要用更系统的检索式、引文追踪和代码/数据复核把它升级或否定。

## 3. 导师可能未展开、但不宜直接说“导师不了解”的问题

不能从一次交流判断导师个人是否知道某篇论文。更稳妥的表达是“交流中尚未展开、需要补证的点”。

### 3.1 BRENDA 的规模不等于训练数据的可用规模

BRENDA 的总条目数很大，但模型训练需要的是与特定任务对齐的样本。必须知道同一条观察是否同时具备：酶/序列 ID、底物或分子 ID、结果值、单位、条件、测量方法、文献定位和证据类型。总量统计无法回答这些问题。

### 3.2 阴性不是一个标签，而是一组证据状态

`inactive`、`no detectable activity`、`below threshold`、`failed expression`、`failed assay`、`not tested`、`not reported` 和“模型推定不活跃”对训练的含义不同。把它们全部编码为 0 会混淆生物事实、实验边界和文献缺失。

### 3.3 “没有记录”不是“没有活性”

这一点在蛋白功能预测中已有 open-world 讨论，在酶底物关系中同样适用。未出现的酶—底物组合可能是未测试、未发表、检索失败或确实无活性；只有明确的实验或检测限信息才能支持阴性解释。

### 3.4 数据质量问题可能比数据量问题更关键

如果补充的阴性记录没有条件、检测限或来源位置，数据量增加可能只是增加噪声。必须用等样本量、等类别比例和严格外推划分做消融，才能判断收益来自阴性语义本身还是来自更多样本。

### 3.5 LLM 的主要风险不是“不会输出 JSON”，而是“看似完整但证据不对齐”

对研究数据而言，最重要的字段不是理由文本，而是原文证据、实体链接、数值和单位、实验条件、数据状态和人工核验状态。

## 4. 建议把研究问题改写成可验证版本

### 4.1 推荐主问题

> 在一个明确的酶学预测任务中，能否从结构化数据库与历史文献中构建来源可追溯的观察级数据，将实测阳性、实测阴性/低于检测限、未测试/未知、删失值和推定标签分开表示，并验证这些区分是否改善模型在序列/底物/实验条件外推场景下的泛化与校准？

### 4.2 两个可选任务

**方案 A：酶—底物兼容性/特异性预测**

- 优点：更容易解释“未测试不等于阴性”；结果可以做分类、排序或概率预测；与底物和条件字段直接相关。
- 风险：需要建立酶、底物、反应和 assay 条件的实体对齐；历史文献的“未反应”表达可能不稳定。

**方案 B：酶序列—功能/变体适应度预测**

- 优点：已有 PU 学习和深度突变扫描文献，阴性监督缺失是明确任务痛点；可以使用序列家族外推和变体工程评价。
- 风险：完整 DMS 数据不一定等于自然文献阴性数据；测量体系和选择压力差异大，需要严格限制研究对象。

如果目标是尽快形成第一篇可验证工作，建议优先方案 A 或一个小型酶家族的方案 B，不要一开始声称覆盖全部分子科学。

### 4.3 最小可行研究设计

1. 固定一个酶家族、底物类别和预测任务；
2. 以 BRENDA/SABIO-RK 为结构化基线，以论文表格和补充材料为文献来源；
3. 建立 50–100 篇论文的人工金标准，至少标注实体、结果、单位、条件、结果类型、证据 span 和记录状态；
4. 比较规则抽取、LLM schema-guided 抽取和人工结果；
5. 训练四组数据：
   - 仅阳性；
   - 阳性 + 未区分的“负例”；
   - 阳性 + 经过证据确认的阴性；
   - 阳性 + 阴性 + 条件/证据/删失信息；
6. 评价抽取 precision/recall/F1、数值与单位正确率、证据定位准确率、字段完整率；
7. 评价模型的 AUROC/AUPRC、排序指标、校准、OOD 泛化和跨 scaffold/序列家族/时间切分性能；
8. 做等样本量、等类别比例、去重和泄漏控制的消融；
9. 若验证阴性记录稀少、噪声过高或没有独立增益，就把工作收缩为“证据感知的酶学文献抽取与数据质量审计”，不要继续包装成通用数据集论文。

## 5. 每个主张的证据等级与写作边界

| 主张 | 当前结论 | 证据等级 | 写作时建议 |
|---|---|---:|---|
| BRENDA 是成熟大型酶学资源 | 已确认 | 高 | 可以直接写，并给官方/论文来源 |
| BRENDA 字段多但不代表观察完整 | schema 与统计支持，完整率需实测 | 中 | 写成“需要审计/初步推断” |
| 酶学数据缺失和条件不完整普遍存在 | 有直接文献审查证据 | 高 | 可以作为问题背景 |
| 某些任务存在可靠阴性缺失 | DMS/PU 有直接证据 | 高 | 限定任务，不泛化到全部分子科学 |
| 阴性数据已有数据库和模型使用 | 已确认 | 高 | 不能说“没人做过” |
| 统一区分阴性、未知、推定和删失仍不成熟 | 有分散工作，但组合证据不足 | 中 | 写成“本轮未发现成熟统一方案” |
| 证据片段与下游增益被统一验证 | 本轮未发现成熟端到端工作 | 中低 | 必须继续系统检索和实验确认 |
| 新 schema 本身能改善模型 | 未知 | 低 | 只能作为待验证假设 |
| LLM JSON 输出能可靠恢复科学事实 | 不成立为一般命题 | 低 | 必须报告字段级正确率和证据对齐 |
| 研究具有论文潜力 | 条件成立 | 中 | 取决于任务收窄、金标准和消融结果 |

## 6. 下一轮调研与决策顺序

### 第一优先级：确认“组合缺口”是否真实

检索式应围绕以下组合，而不是只搜 negative data：

- `enzyme` + `negative` + `assay context` + `literature mining`
- `enzyme substrate specificity` + `inactive` + `untested`
- `enzyme kinetics` + `censored` + `below detection limit`
- `protein sequence function` + `positive-unlabeled` + `experiment`
- `enzyme data extraction` + `negative result` + `supplementary table`
- `enzyme benchmark` + `negative examples` + `OOD/generalization`
- `BRENDA` + `completeness` / `missing metadata` / `machine learning`

每个候选工作需要记录：任务、数据来源、阴性定义、是否实测、是否保留条件、是否有证据位置、是否公开数据、是否做下游比较。

### 第二优先级：对 BRENDA 做一项可复现审计

不是重新建库，而是回答：

- 哪些字段在同一观察上共现？
- 哪些记录有 reference 但没有原文位置？
- 是否能区分 inhibitor、no activity、not reported 和 untested？
- 数值是否保留单位、范围、删失符号和 assay 条件？
- 与一个具体任务的输入—输出是否能直接对齐？

### 第三优先级：做最小下游实验

只要一个任务、一个酶家族或一个底物体系，重点验证“可靠阴性和上下文是否具有独立价值”，不要先做覆盖所有分子科学的统一数据集。

---

## 7. 暂定研究定位

目前最稳妥的定位是：

> 面向酶学机器学习任务的证据感知数据构建：从结构化数据库和科学文献中恢复并区分阳性、阴性、未知、删失和推定监督，同时保留实验条件与来源证据，评估这些数据语义改进对模型泛化和校准的实际作用。

这个定位有三个优点：

1. 不与 BRENDA、SABIO-RK、STRENDA、EnzymeML 的既有工作正面重复；
2. 能把“阴性数据挖掘”保留为核心案例，但不把研究锁死在简单的 0/1 标签；
3. 研究结论可以被证伪：如果证据化阴性没有改善模型，仍然能得到关于数据构建和任务适用性的结果。
