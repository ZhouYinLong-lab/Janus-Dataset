# 批量提取入口

现在使用 [batch.py](batch.py)：自动串联正文扫描、阴性原句发现、条件补充、逐字段引用检查、隔离、去重及JSON/CSV导出。同一工作区重新运行会跳过已完成任务，已经取得的响应可离线恢复，未知执行结果不自动重发。

工程已接通，并完成5篇材料的真实调用：18个正文发现分块全部执行，10条机械通过记录中6条核心陈述获助手支持、4条隔离；两个补全请求结果未知。另10篇质量队列和三组问答已执行，累计132/200次生成，当前没有在途任务。质量组11条记录仍有条件和类型缺口，不能无人复核直接入训。结果见[本轮执行记录](运行记录.md)及[问答对照](问答对照结果.md)。

## 已准备的两组材料

5篇工程材料位于 `local/batch_engineering_02`，18个正文分块；另10篇质量材料位于 `local/batch_quality_02`，45块。均使用全文可读正文，无输入缺口。分组与接触历史见 [batch_cohorts.json](batch_cohorts.json)，不能称为独立专家盲测。

每块先有一次发现调用，空结果不补全；每8条合格候选最多组成一个补全请求。因此5篇按每块一个补全批次估算是18＋18次，另10篇是45＋45次；候选多时需要更多补全批次，这些不是严格调用上界。实际调用以共享账本上限保护，不以论文篇数计费。

`batch_engineering_01`、`batch_quality_01` 是代码审查修订前的离线准备快照，没有调用过生成接口；当前不使用。旧B022的 `local/two_stage_01` 状态及未决请求保持原样，不重发。

## 在已授权的共享预算下续跑

进入项目根目录，使用现有Python环境，不需要安装SDK。`.env` 已在本机保存，命令不包含密钥。

本机已建立 `local/round_01_budget.json`：本轮累计200次生成、800万保守token预留，涵盖提取、型号检查和问答。不要再创建或重置它。下面仅示意新环境如何在获得同等明确授权后建立预算；执行失败、已知重试也计数，实际用量和费用以服务回执及账单为准。

```powershell
Set-Location D:/Projects/Dog/Janus-Dataset
D:/Environment/Miniconda3/python.exe research/2026-10-25-api-extraction/batch.py budget --ledger research/2026-10-25-api-extraction/local/round_01_budget.json --max-requests 200 --max-reserved-tokens 8000000 --authorization "仅新环境且用户明确确认这组上限后创建；本机已有账本不要执行"
```

这条命令自动处理并导出5篇工程材料；中断后仍用同一命令续跑。本机这一组已执行完可运行的任务，再次运行不会补发未知请求，也不会解决既有语义问题：

```powershell
D:/Environment/Miniconda3/python.exe research/2026-10-25-api-extraction/batch.py run --workspace research/2026-10-25-api-extraction/local/batch_engineering_02 --config research/2026-10-25-api-extraction/batch.config.example.json --ledger research/2026-10-25-api-extraction/local/round_01_budget.json --env-file research/2026-10-25-api-extraction/.env --live
```

共享账本与配置中的工作区上限同时生效，取更严格的限制；200次是全流程合计，不是每个工作区各200次。原 `config.local.json` 仍为1次上限，没有被修改；批量使用 `batch.config.example.json`。后续质量提取和RAG继续用同一本账本。

不加 `--live` 不会发生成请求。`--max-new-requests 2` 可额外限制单次启动，但不能突破累计上限。`--retry-known` 只允许HTTP429/500明确失败的一次重试；它不能重发未知结果。

## 看结果与失败

每个工作区的 `exports` 包含：`records.json`、Excel可打开的 `records.csv`、`discovery_candidates.json`、`quarantine.json`、`unresolved.json`、`failures.json`、`job_coverage.json`、`summary.json`。其中发现失败、全部隔离、补全未运行、返回空候选分别显示；输入不可读与未处理部分也保留。

每条结果附来源哈希、原文引文和候选关联。严格相同的记录合并，限定条件或解释不同的版本保留；记录数不等于独立实验数。机械检查通过的记录仍待语义复核，默认不可直接训练。

不付费查看当前状态或重新导出：

```powershell
D:/Environment/Miniconda3/python.exe research/2026-10-25-api-extraction/batch.py status --workspace research/2026-10-25-api-extraction/local/batch_engineering_02
```

单个未知结果阻断该任务及其补全，独立任务在授权预算内继续；鉴权、余额问题或连续两次网络断开会停发全部请求。退出码3表示仍有预算停止、失败或输入缺口，不可当成完整验收通过。锁文件留存时先核查其中PID对应进程是否已结束；不要删除锁后盲目重发。
