# MolGlueDB 来源文献的正文阴性提取

本版依次整理来源、取得全文、扫描正文、补充候选条件、检查引文并导出。提取对象是已做实验在正文叙述中报告的阴性结果。正式全库入口需要固定五篇验收通过。

## 三个启动文件

1. 双击 `准备与检查.cmd`：创建来源清单，逐篇尝试公开全文，准备任务并检查预算。不发送模型生成请求。获取范围包括所有可核验来源，下载可能持续较长时间；逐篇状态保存在本地。
2. 双击 `启动或续跑.cmd`：通过验收、版本和预算检查后开始提取。再次点击会续跑；已有进程运行时第二次启动会拒绝。用户主动启动可恢复操作暂停，服务故障暂停会保留。
3. 双击 `查看进度与结果.cmd`：只读查看状态并打开汇总；全文准备尚未完成时先显示来源获取进度。

第一次准备会在 `local/molglue_launch.json` 写入本机设置：原始数据库导出、来源目录、工作区、模型配置、密钥环境文件、预算及验收文件路径。原文和运行文件均保留在被忽略的 `local/`。密钥使用原有 `.env` 中的 `JANUS_API_KEY`；配置和日志不包含密钥。

当前解释器优先使用 `D:/Environment/Miniconda3/python.exe`，不可用时使用 `python`。依赖为 BeautifulSoup、PyMuPDF、psutil；已有 XML 解析和 API 适配沿用项目实现。

## 来源范围及输入缺口

范围以冻结的 MolGlueDB 来源清单为准。数据库条目数、来源数和成功处理论文数分别统计，公司材料不并入论文数。论文所称241篇与实际可核验来源的差异保留为范围缺口。

全文优先 XML，其次 HTML、文字版 PDF。正文发现不读摘要、参考文献或图像；图表文字只按引用关系补充条件。扫描页、双栏顺序不清和缺失附件保留为输入缺口。没有获得全文、解析失败、未发现候选分别记录。

HTML/PDF 默认需要针对文件的版式核查。补入原文时，在该论文的 `papers.json` 元数据中记录 `format_review`：`source_sha256`、`parser_sha256`（对应 `source_formats.py`）、`body_order_checked:true`、`body_boundaries_checked:true` 和复核者身份。文件或解析器变化会使该核查失效。PDF只处理可确认顺序的正文，部分解析的覆盖限制会随记录保留。

## 命令入口

所有命令都通过 `batch_candidate.py`。`sources` 整理来源；`fetch` 获取全文；`prepare` 冻结任务；`check` 显示输入与预算；`run` 运行；`status` 只读查看；`export` 导出；`acceptance` 汇总固定验收并生成放行或阻碍记录。完整参数可用 `--help` 查看。

固定验收使用 `prepare --phase pilot`，默认论文为 B212、B207、B235、B203、B296。正式提取使用 `run --phase full --acceptance 验收文件 --live`。两者共用现有预算，不因新工作区增加额度。

启动前需把参考放入验收工作区的 `acceptance_reference.json`，注明逐篇正文覆盖、预期阴性及疑问、`expert_gold:false`。首次运行冻结其哈希。真实运行结束后，对当前输出逐条复核，评价原句、对象、终点、条件及漏提；把复核结果交给 `acceptance`，生成绑定代码、提示词和模型的放行记录。只有配置文件和测试通过不能产生放行记录。

## 结果

- `records.json/csv`：记录、条件、引文和各来源追溯信息；自动输出均待内容复核。
- `paper_coverage.csv`：每个来源的输入情况、完成分块和覆盖缺口。
- `candidate_audit.csv`：每条候选的接受、隔离、未解决去向，以及该来源自己的字段状态。
- `failures.csv`：失败任务及原因。
- `summary.md/json`：来源覆盖、候选去向、用量和停止原因。

同一正文段落可以产生多条候选，每条保留原句。补充阶段提供完整的可读正文单元；同段其他句子可以支持对象与条件，但仍需正确归属。超长上下文先拆小候选批次；单条仍放不下时留下缺口，不把未提供的材料说成全篇未报告。

结果未知的生成请求不自动重发。已保存完整响应优先离线恢复；成功结果续跑直接复用。断电或中止后，重启先核对运行进程、请求和预算。强行结束连接可能留下计费未知任务；这些任务会保留并单列。

## 版本与提交

每个新工作区自带 `runtime/` 代码快照，输入、提示词及源码均有哈希。运行中的工作区不混用新版本。旧入口改动前的本机代码副本另存于 `local/frozen_runtime/9d39474/`，历史工作区与账本未重置。

本版一次只运行一个付费进程，预算到限会停在当前进度；来源部分完成不能报告为全库完成。后续RAG和训练使用另行冻结的任务与对照。

## 无人值守接续（2026-10-27）

`candidate_autorun.py --settings 本机设置 --run-dir 运行目录 --diagnosis 诊断文件` 依次运行验收队列、获取剩余公开全文、准备全库工作区，并检查正式放行条件。内容复核未完成时保留阻碍，不把自动输出填成已支持。状态与汇总保存在运行目录；`查看进度与结果.cmd` 同时显示当前后台阶段。

新运行可以显式使用 `run --network-route direct` 直连同一个已授权服务；不修改系统代理，不在一次付费请求失败后自动切换线路重发。请求保存连接阶段、读取字节数、耗时及异常类型，流式片段只保留在本地并做密钥脱敏。已知未知请求继续按原文范围阻止重复。

一次性的网络恢复要求同一服务、同一模型的非生成直连诊断成功，并在共享账本留下恢复原因。相同诊断不能被反复用于清除连续故障暂停。预算上限与历史请求始终保留。
