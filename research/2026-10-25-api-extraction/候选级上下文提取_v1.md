# 候选级上下文提取 v1

更新：2026-10-26。

## 改动目的

正文发现仍扫描全部正文段落。候选补充阶段不再把同一正文块里所有候选都配给同一大段上下文，而是为每条候选单独整理：候选原句、正文明确引用的图表、相邻正文，以及少量与候选词汇相符的方法段落。整批候选共享原管线的 18,000 字符上下文上限；按图表引用、相邻正文、方法段落的顺序轮流分配，避免候选数量放大输入长度。

上下文可在不同候选之间去重后共同发送，但每条候选都带有自己的允许证据单元列表。返回记录引用了另一候选的上下文，或引用锚点段落中不属于该候选原句的内容时会隔离。因共享上限未发送的上下文单元会记入候选审计信息。

## 逐字段状态

每个返回记录都要求 `field_search_status`，对每个提取字段标记：

- `supported`：字段有值，并带该字段的原文引文。
- `not_found_in_supplied_context`：本次给模型的候选上下文里没有可用值；不代表整篇论文没有。
- `ambiguous_in_supplied_context`：上下文有相关信息，但不能确定属于这条实验结果。

字段状态与提取值不一致、缺少状态、或引用了其他候选的单元，会写入状态问题或隔离记录。空值仍保留为空，不根据全文其他实验猜填。

## 使用

先用新入口准备工作区；它沿用原批处理的来源哈希、共享预算和请求记录，但冻结新版本提示词与代码哈希：

```powershell
D:/Environment/Miniconda3/python.exe research/2026-10-25-api-extraction/batch_candidate.py prepare --workspace research/2026-10-25-api-extraction/local/candidate_context_01 --manifest PATH_TO_PAPER_MANIFEST.json --limit 241
```

准备阶段不调用模型。查看预算与工作区后，显式启动：

```powershell
D:/Environment/Miniconda3/python.exe research/2026-10-25-api-extraction/batch_candidate.py run --workspace research/2026-10-25-api-extraction/local/candidate_context_01 --config research/2026-10-25-api-extraction/batch.config.example.json --ledger research/2026-10-25-api-extraction/local/round_01_budget.json --env-file research/2026-10-25-api-extraction/.env --live
```

现有旧工作区和旧结果不改写，也不能用普通入口续跑这个新版本。`exports/field_search_status.csv`与`records.json`保存逐字段检索状态。该状态来自模型对给定上下文的自报，仍需依据引文和原文复核。

## 当前边界

此版本没有调用 API，也没有实测其准确率。它针对已观察到的上下文串用和字段漏提设计了更窄的证据输入与机械边界。方法段落的词汇匹配仍可能漏掉跨段实验条件，也可能选到仅词汇相似的段落；状态标签本身不是金标准。切换全库前应先用已有失败案例检查请求内容和隔离结果。
